# Automatic build runbook

Reconcile handoff and actual source → choose eligible feature → specify observable behavior → implement → run meaningful checks → repair → integrate → independent read-only review → repair and re-review → record evidence → write handoff last → continue.

Routine checks and repairs are automatic. Ask only for a genuine external dependency that prevents further independent progress. Never replace live saving with success messages or lower acceptance to bypass failures.

Workers report paths, observed behavior, checks, unresolved issues, and unavailable usage honestly. Keep ownership disjoint; Sites owner authors all source. Escalate conflicting contracts or data integrity concerns immediately; after two distinct failed fixes ask an independent strong agent to diagnose, then root implements its correction and rechecks. Do not retry unchanged failures.

Before completion, integrate all features, run project checks and desktop/mobile interaction tests, obtain independent review, publish a built version from the exact pushed commit, and verify deployment status. Private access remains private. Preserve the continuous preview until publication. Update plan, evidence, decisions, ledger and handoff.

At a context boundary, save exact current state, processes, active feature and next command. Do not create background automation. Resume with the saved prompt. Unknown telemetry is unknown, not zero.
